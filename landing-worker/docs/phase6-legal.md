# Phase 6B — นโยบายความเป็นส่วนตัว ข้อกำหนด และการลบข้อมูล (Z.AI)

สัญญากลาง Claude เป็นเจ้าของ ห้ามเปลี่ยนเอง ถ้าต้องเปลี่ยนให้เขียนขอใน `docs/legal-integration-status.md`
กติการ่วมทั้ง 8 ข้อใน `docs/phase1-tasks.md` ใช้ด้วย

## ทำไมต้องทำก่อนเปิดใช้

เว็บยังไม่มีหน้ากฎหมายเลย และบริการภายนอกที่ต้องสมัครใน `docs/DEPLOY.md` ข้อ 1 ขอ URL เหล่านี้ตอนยื่นอนุมัติ:
- **Meta App Review**: Privacy Policy URL และ User Data Deletion (หน้าบอกวิธีขอลบข้อมูล)
- **Google OAuth consent screen**: Privacy Policy และ Terms of Service URL
- **Omise**: เว็บร้านค้าต้องมีข้อกำหนด นโยบายคืนเงิน และช่องทางติดต่อ
- **PDPA**: ต้องแจ้งว่าเก็บข้อมูลอะไร เพื่ออะไร ส่งให้ใคร เก็บนานเท่าไร และสิทธิของเจ้าของข้อมูล

## Branch และไฟล์ที่เป็นเจ้าของ

แตก branch `feat/legal` จาก `main` ล่าสุด

`public/legal/**` (หน้าใหม่ทั้งหมด), `tests/legal.test.cjs`, `docs/legal-integration-status.md`
แก้เพิ่มได้เฉพาะจุด: ลิงก์ท้ายหน้าใน `public/index.html` (`<footer class="site-footer">`), ข้อความใต้ฟอร์มใน `public/login/index.html`
("การเข้าสู่ระบบถือว่ายอมรับข้อกำหนดและนโยบายความเป็นส่วนตัว" พร้อมลิงก์), ลิงก์เล็กๆ ท้าย `public/app/billing/index.html`

**ห้ามแก้** `src/**`, `migrations/**` — งานนี้เป็นหน้าเว็บล้วน ไม่มี API ใหม่

## หน้าที่ต้องมี (ภาษาไทย)

| URL | เนื้อหา |
|---|---|
| `/legal/privacy/` | นโยบายความเป็นส่วนตัว (PDPA) |
| `/legal/terms/` | ข้อกำหนดการใช้บริการ: เครดิต แพ็กเกจ การต่ออายุ การใช้งานที่ห้าม ความรับผิดต่อเนื้อหาที่ AI สร้าง |
| `/legal/refund/` | นโยบายคืนเงิน/ยกเลิก: เครดิตที่ใช้ไปแล้ว งานที่ล้มเหลวคืนเครดิตอัตโนมัติ ช่องทางขอคืนเงิน |
| `/legal/data-deletion/` | วิธีขอลบบัญชีและข้อมูล (ใช้เป็น Data Deletion URL ของ Meta) |

**ข้อมูลในนโยบายต้องมาจากโค้ดจริง ห้ามเดา** — อ่านโค้ดแล้วเขียนตารางลง `docs/legal-integration-status.md` ก่อนเขียนหน้า:
ข้อมูลอะไร / เก็บที่ไหน (ตาราง, R2, ไม่เก็บ) / ส่งให้ผู้ให้บริการรายไหน / ไฟล์ที่ยืนยัน
เช่น เบอร์โทร (`auth_identities`, ส่ง ThaiBulkSMS), อีเมล Google, รูปและรายละเอียดสินค้า (ส่ง Anthropic? เก็บไหม? ดู `src/affiliate.ts`, `public/review/`),
ข้อความลูกค้าในกล่องข้อความและ token เพจ (`src/inbox/`, `src/social/`), การชำระเงิน (Omise — เราเก็บอะไร ไม่เก็บเลขบัตร?), ใบเสร็จ (`src/receipts/` — ต้องเก็บตามกฎหมายภาษี),
cookie `naka_session`, Turnstile, Cloudflare, Google TTS

## ค่าที่เจ้าของธุรกิจต้องกรอก

ห้ามแต่งชื่อบริษัท ที่อยู่ เลขผู้เสียภาษี อีเมล หรือเจ้าหน้าที่คุ้มครองข้อมูล ใส่เป็นช่องที่เห็นชัด เช่น `<span class="fill-me">[ชื่อผู้ประกอบการ]</span>`
และรวมรายการช่องทั้งหมดไว้ใน `docs/legal-integration-status.md` ชื่อที่ใช้บนเว็บตอนนี้คือ "NAKA-AI Tech" ใช้เป็นชื่อบริการได้
ใส่ "ปรับปรุงล่าสุด: <วันที่>" บนทุกหน้า และหมายเหตุใน status doc ว่า **ควรให้ผู้รู้กฎหมายตรวจก่อนใช้จริง**

## หน้าตา

- หน้าเอกสารอ่านง่าย: หัวข้อชัด สารบัญบนหน้า ตัวอักษรขนาดอ่านสบาย สไตล์เดียวกับหน้าแรก (`public/home.css`/ฟอนต์เดิม) ใช้ CSS ร่วมไฟล์เดียว `public/legal/legal.css`
- ใช้ได้ที่ 360px ไม่ล้นจอ, ไม่มี JavaScript ที่จำเป็น, ไม่ใส่ `noindex` (Meta/Google ต้องเข้าถึงได้)
- ทุกหน้ามีลิงก์ไปหากันและกลับหน้าแรก

## เทสที่ต้องมี (`tests/legal.test.cjs`)

- ทั้ง 4 ไฟล์มีอยู่, มี `<title>` และ `<h1>`, `lang="th"`, ไม่มี `noindex`
- ลิงก์ภายในทุกลิงก์ใน `public/legal/**` ชี้ไปไฟล์ที่มีจริง
- หน้าแรก, `/login/` และ `/app/billing/` มีลิงก์ไป `/legal/privacy/` และ `/legal/terms/`
- ช่อง `fill-me` ทุกช่องอยู่ในรายการของ status doc (เทสนับให้ตรงกัน)

## ก่อนส่งงาน

`npm run typecheck` และ `npm test` ต้องผ่านทั้งหมด **commit งานลง branch** (อย่าทิ้งไว้ uncommitted และอย่า commit ไฟล์ probe/ทดลอง)
เปิดทุกหน้าด้วย `npm run dev` ที่จอกว้างและ 360px แล้วสรุปใน `docs/legal-integration-status.md`
