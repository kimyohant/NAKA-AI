# Phase 6A — สถานะ integration ผลงานของฉัน

Branch: `feat/works` (เริ่มจาก `main` commit `812ee92`)

## งานที่ส่ง

- `src/works/index.ts` ส่งออก `handleWorks(request, env, url, userId)` สำหรับ `GET /api/works` หลังตรวจ session แล้ว เลือกเฉพาะงาน `AFFILIATE_JOB_KIND` ของผู้ใช้ เรียง `created_at DESC, id DESC` และแบ่งหน้าครั้งละ 20 รายการด้วย cursor คู่วันที่และ id
- ส่งเฉพาะ `id`, `kind`, `title`, `status`, `costCredits`, `createdAt`, `finishedAt`, `href`; ไม่ส่ง input/output/error/ต้นทุนผู้ให้บริการ ชื่อสินค้าจาก JSON ที่เสียหรือไม่มีชื่อใช้ “คลิปรีวิว”
- `/app/` มีส่วน “ผลงานของฉัน” แสดงเวลาไทย สถานะ เปิดดู รีเฟรช ดูเพิ่ม สถานะว่างและข้อผิดพลาดในส่วนนี้ พร้อม `?mock=1` สำหรับพรีวิว
- `/review/?job=<id>` เรียก API สถานะทันทีเมื่อเปิดหน้า และหลัง POST สร้างงานสำเร็จจะใส่ job id ลง URL เพื่อให้รีเฟรชกลับมาดูงานเดิมได้

## ผลตรวจ

- `npm run typecheck` ผ่าน
- `npm test` ผ่านทั้งชุด (163 เทส) รวมสิทธิ์เจ้าของงาน การกรองงานตอบแชท ฟิลด์ที่ห้ามรั่ว ชื่อสำรอง pagination 45 งานที่เวลาเท่ากัน ข้อผิดพลาดฐานข้อมูล และ DOM จำลองของหน้ารีวิว
- `npm run dev` เสิร์ฟ `/app/?mock=1`, `/app/works.js`, `/app/works.css`, `/review/?job=test-id` เป็น HTTP 200
- ยังทดสอบวงจรสร้างคลิปจริง → ปิดแท็บ → เปิดจาก `/app/` ไม่ได้ใน branch นี้: `/api/works` เป็น HTTP 404 จนกว่า Claude จะต่อ route ใน `src/index.ts` ตามสัญญา และเครื่องทดสอบไม่มีเบราว์เซอร์ที่เชื่อมต่อให้เปิดหน้าแบบโต้ตอบ ไม่มีการอ้างว่าทดสอบปลายทางนี้ผ่าน

## งานต่อที่เจ้าของสัญญากลางต้องทำตอน merge

1. ต่อ `handleWorks` ใน `src/index.ts` สำหรับ `/api/works` หลัง `requireUser` แล้วส่ง `user.id` ให้ handler; ผู้ที่ไม่ล็อกอินต้องได้ 401 ก่อนเรียก handler ห้ามเปลี่ยนสัญญา API
2. รันวงจรบนเบราว์เซอร์จริงด้วยบัญชีและ provider ที่ตั้งค่าไว้: สร้างคลิปรีวิว ปิดแท็บ เปิด `/app/` และกด “เปิดดู” จากรายการ แล้วตรวจ `queued`/`running`/`done`/`failed` รวมถึงจอ 360px
3. รูปสินค้าถูกเก็บบนอุปกรณ์ผู้ใช้เท่านั้นตามระบบรีวิวเดิม จึงไม่สามารถกู้ไฟล์วิดีโอหรือรูปเดิมหลังปิดแท็บได้; งานเดิมเปิดดูบท เสียง และแคปชันจาก server ได้ แต่ปุ่มสร้างวิดีโอของหน้ารีวิวเดิมจะใช้ภาพตัวอย่างเมื่อไม่มีรูปที่เลือกไว้ หากเป้าหมายคือเปิด *วิดีโอเดิม* ต้องมีสัญญาเพิ่มเติมเรื่องการบันทึกวิดีโอหรือให้ผู้ใช้เลือกรูปเดิมใหม่ก่อน render โดยคงขอบเขตความเป็นส่วนตัวของรูปสินค้าไว้
