# ราคาเครดิต และงานล่าสุดบนแดชบอร์ดสมาชิก

เครดิตของสมาชิกมีที่เดียว คือ ledger ใน schema `account` ของ naka-ai.com (`apps/landing`, ADR-0004) เอกสารนี้อธิบาย 3 เรื่อง:

- งานแต่ละอย่างหักเครดิตเท่าไร: เจ้าของตั้งเองใน `/admin/system/` แท็บ "แพ็กเกจและราคา" ส่วน "ราคาเครดิต"
- Naka Studio หักเครดิตอย่างไร
- แดชบอร์ด `/app/` เห็นงานของสตูดิโอได้อย่างไร

โควตารายเดือน (`docs/entitlements.md`) ยังทำงานเหมือนเดิม และใช้คู่กับเครดิต:

- **เครดิต** คิดราคางานทุกชิ้น
- **โควตา** จำกัดจำนวนงานแพงต่อเดือน

## ภาพรวม

```
naka-ai.com (landing)                                   Naka Studio
┌──────────────────────────────┐                        ┌────────────────────────────────────┐
│ /admin/system/ → ราคาเครดิต    │                        │ generateImage / generateVideo      │
│   PUT /api/admin/system/prices │                        │   └ createTask (จุดเดียวที่สร้างงาน)    │
│ /app/  → ประวัติเครดิต          │  GET /api/v1/system/   │       ├ taskCredits()  ← ราคา        │
│        → ผลงานล่าสุด ───────────┼─ member-works?owner= ─▶│       ├ INSERT sys_task             │
│   GET /api/me/works            │  X-Admin-Token         │       └ hold_credits()  (tx เดียวกัน)  │
│   GET /api/me/credits          │  (server → server)     │ เสร็จ → commit_hold / ล้ม,ยกเลิก,ลบ →  │
└──────────────┬───────────────┘                        │        refund_hold / unknown → ค้างไว้   │
               │                                        └───────────────┬────────────────────┘
               ▼                                                        ▼
        ┌────────────────────────── PostgreSQL schema account ──────────────────────────┐
        │ credit_prices (SELECT → studio_app) · credit_ledger · credit_holds             │
        │ hold_credits / commit_hold / refund_hold (EXECUTE → studio_app, 0002_shared)   │
        └────────────────────────────────────────────────────────────────────────────────┘
```

## ราคาเครดิต (`account.credit_prices`, migration `0006_credit_prices.sql`)

| key | งาน | ค่าเริ่มต้น | คิดต่อวินาทีได้ |
|---|---|---|---|
| `studio.video` | Naka Studio: สร้างวิดีโอ | 5 ต่อคลิป | ได้ |
| `studio.image` | Naka Studio: สร้างภาพ | 0 (ฟรี) | — |
| `landing.ai_video` | วิดีโอ AI บนหน้าเว็บ | 5 (หรือค่า `AI_VIDEO_CREDITS` ที่เคยบันทึก) | — |
| `landing.clips` | คลิปรีวิวสินค้า | 1 | — |
| `landing.marketer` | นักการตลาด AI บนหน้าเว็บ | 1 | — |

กติกา:

- **0 = ฟรี** ไม่หักเครดิต และไม่สร้าง hold
- **ปัดขึ้นเป็นจำนวนเต็มเสมอ** (`creditsFor`) และใช้กติกาเดียวกันทั้งสองแอป
  - ราคาต่อชิ้นต้องเป็นจำนวนเต็ม
  - ราคาต่อวินาทีมีทศนิยมได้ 2 ตำแหน่ง เช่น 0.5 × 5 วินาที = 2.5 → ปัดเป็น 3
  - ความยาวที่ไม่รู้นับเป็น 1 วินาที
- **ราคาใหม่ใช้กับงานที่เริ่มหลังบันทึก**
  - งานที่ถือเครดิตไปแล้วคิดตามราคาเดิม
  - สตูดิโออ่านราคาใหม่ภายใน 15 วินาที
- **ทุกการแก้บันทึก audit** (`system_audit` area `price`) พร้อมเหตุผล
  - เป็น compare-and-set: ถ้าแอดมินสองคนแก้พร้อมกัน คนที่สองได้ 409 ราคาจึงไม่ถูกทับโดยไม่รู้ตัว
- **`AI_VIDEO_CREDITS` เลิกใช้แล้ว**
  - migration ย้ายค่าที่เคยบันทึกเข้าตารางนี้ แล้วลบออกจาก `system_settings`
  - ราคาจึงมีที่ตั้งที่เดียว

ทำไมภาพในสตูดิโอเริ่มที่ 0:

- ละคร 1 เรื่องใช้ภาพตัวละคร ฉาก และสตอรีบอร์ดหลายสิบภาพ แพ็กเกจเริ่มต้น (30 เครดิต) จึงจะหมดก่อนได้วิดีโอ
- ต้นทุนหลักอยู่ที่วิดีโอ ซึ่งมีโควตารายเดือนคุมอีกชั้น
- เจ้าของเปลี่ยนเป็นมีราคาได้ทุกเมื่อ

## สตูดิโอหักเครดิต (`apps/studio/backend/src/core/auth/credits.ts`)

**ใครถูกหัก:** สมาชิก naka-ai ที่ล็อกอินผ่าน SSO เท่านั้น เหมือนกติกาของโควตา

ไม่หักในกรณีต่อไปนี้:

- แอดมิน
- แถวของโหมด single-user (`local`)
- `NAKA_ENTITLEMENTS=off` หรือ `NAKA_CREDITS=off`
- สตูดิโอที่ไม่ได้ต่อฐานข้อมูลร่วม

**ใครจ่าย:** เจ้าของโปรเจกต์ (owner ของละคร) ซึ่งเป็นคนเดียวกับที่ถูก stamp ลงงาน และคนเดียวกับที่ถูกนับโควตา

**ลำดับเมื่อสร้างงาน:**

1. นับโควตาวิดีโอ (`useVideoQuota`)
2. อ่านราคา (`taskCredits`) นอก transaction
3. ใน transaction เดียวกัน: INSERT `sys_task` → `hold_credits(owner, credits, 'studio:<image|video>:<task id>')` → บันทึก `credit_hold_id` และ `credits_charged`
4. ถ้าเครดิตไม่พอ:
   - `hold_credits` ตอบ `ok = false` และโค้ดตอบ `E_CREDITS_INSUFFICIENT` เป็นข้อความไทย บอกว่างานนี้ใช้กี่เครดิตและเหลือกี่เครดิต
   - transaction ย้อนกลับ จึงไม่มีงานค้าง
   - โควตาที่นับไปแล้วถูกคืน

**ปิดงาน:**

| งานจบแบบ | เครดิต |
|---|---|
| เสร็จ (`completed`: ภาพ URL, ภาพ base64, วิดีโอ) | `commit_hold` ตัดจริง |
| ล้ม (`failTask`) / ยกเลิก (`cancelGenerationTask`) / ลบงานที่ยังไม่เสร็จ (`DELETE /tasks/:id`) | `refund_hold` คืนครั้งเดียว |
| สถานะไม่รู้ (`unknown`) | ถือค้างไว้ จนกว่าจะ resume แล้วเสร็จหรือล้ม หรือถูกยกเลิกหรือลบ |

- `commit_hold` และ `refund_hold` เรียกซ้ำได้โดยไม่เกิดผลซ้ำ (idempotent)
- ถ้าเรียกไม่สำเร็จ ระบบแค่ log ไว้ และ hold ยังเห็นใน `account.credit_holds`

**ในประวัติเครดิตของสมาชิก:** ref ของ hold ถูกแปลงเป็นคำที่ลูกค้าอ่านเข้าใจ เช่น "สร้างวิดีโอใน Naka Studio" หรือ "คืนเครดิต: สร้างภาพใน Naka Studio ไม่สำเร็จ" ตัว ref เองไม่ถูกส่งออก

## ผลงานล่าสุดบนแดชบอร์ด

- สตูดิโอมี endpoint `GET /api/v1/system/member-works?owner=<id>&limit=5`
  - เป็น admin-only เหมือน `/system/overview`
  - รวมละคร วิดีโอรีวิวสินค้า โพสต์ขาย โคลนไวรัล และแคมเปญ ของสมาชิกคนนั้น เรียงจากแก้ล่าสุด
  - ตัดชิ้นที่เป็นไส้ในของงานอื่นออก งานที่สมาชิกเริ่มจึงขึ้นครั้งเดียว:
    - ละครที่อยู่เบื้องหลังวิดีโอรีวิว แคมเปญ หรือ variant ของโคลน
    - โปรเจกต์วิดีโอที่อยู่เบื้องหลังโพสต์ขาย
- landing มี endpoint `GET /api/me/works`
  - ถามสตูดิโอแบบ server-to-server ด้วย `STUDIO_INTERNAL_URL` + `STUDIO_ADMIN_TOKEN` สำหรับผู้ที่ล็อกอินอยู่เท่านั้น
  - ไม่ follow redirect และ timeout 4 วินาที
  - กรองลิงก์ให้ชี้ไปหน้างานของสตูดิโอเท่านั้น (`STUDIO_URL` + `/drama|studio|seller|viral-clone|marketer/<id>`)
  - ถ้าสตูดิโอไม่ตอบ จะได้ `{ available: false }` แดชบอร์ดยังโหลดได้ และยังมีปุ่ม "เปิด Naka Studio" เหมือนเดิม

## ทางเลือกที่พิจารณา

| ทางเลือก | ข้อดี | ข้อเสีย | ผล |
|---|---|---|---|
| ราคาในตาราง `account.credit_prices` (เลือก) | ที่เดียวสำหรับทั้งสองแอป · audit · สตูดิโออ่านด้วย grant SELECT เหมือน `member_features` | ต้องมี migration และหน้าแอดมินใหม่ | ✔ |
| ราคาเป็น system setting (`AI_VIDEO_CREDITS` แบบเดิม) | ไม่ต้องสร้างตาราง | `system_settings` มีค่าลับปน จึงเปิดให้สตูดิโออ่านไม่ได้ · ไม่มีหน่วยต่อวินาที | ✘ |
| ราคาเป็น env ของสตูดิโอ | ง่ายที่สุด | ต้อง deploy ทุกครั้งที่เปลี่ยนราคา และราคาแยกกันสองที่ | ✘ |
| ผลงานล่าสุด: landing อ่านตารางของสตูดิโอเอง | ไม่ต้องเรียก HTTP | กลับทิศของ ADR-0004 (account เปิดให้สตูดิโอ ไม่ใช่สตูดิโอเปิดให้ account) · ผูก schema ของสองแอปเข้าด้วยกัน | ✘ |
| ผลงานล่าสุด: endpoint ของสตูดิโอ + admin token (เลือก) | ใช้ช่องทางเดียวกับ `/admin/studio-system/` · สตูดิโอเป็นเจ้าของข้อมูลของตัวเอง | ถ้าสตูดิโอล่ม ส่วนนี้จะหายไป (แต่หน้ายังโหลดได้) | ✔ |

## สิ่งที่ควรกลับมาดูเมื่อระบบโต

- **hold ที่ค้างจากงาน `unknown` นานเกินไป:** ยังไม่มี cron คืนให้อัตโนมัติ
  - ตอนนี้แอดมินยกเลิกงานได้จาก `/admin/studio-system/` และการยกเลิกจะคืนเครดิต
  - ถ้าเกิดบ่อย ควรมี sweep (เช่น unknown เกิน 24 ชั่วโมง → refund)
- **settle ที่ล้มเพราะฐานข้อมูลไม่ตอบ:** ตอนนี้แค่ log ไว้
  - ถ้าเกิดจริง ควรมีงานกวาดที่จับคู่ `sys_task` (completed/failed) กับ `credit_holds` (held)
- **งานข้อความ (LLM) ในสตูดิโอยังไม่คิดเครดิต**
  - ถ้าจะคิด ให้เพิ่มแถวใน `credit_prices` แล้วเรียก `taskCredits` และ `holdTaskCredits` ที่จุดสร้างงานนั้น
- **`member-works` เป็น UNION ข้าม 5 ตาราง:** เร็วพอสำหรับ 5 แถวต่อสมาชิก
  - ถ้าตารางใหญ่มาก ให้เพิ่ม index `(owner_user_id, updated_at)` ในแต่ละตาราง
